# HTTP-журналирование: ограничение тел и исключения

Правило относится к входящим и исходящим HTTP-запросам пакета `atlcom/laravel-helper`.
Оно описывает ограничение данных журнала из изменения CRM-173 и сохранение прежней фильтрации.
Тело реального HTTP-запроса, ответа и данные HTTP-кеша этим ограничением не изменяются.

## Ограничение данных

- `http_log.data_max_length` задаёт максимальное число байт тела в `HttpLogDto`.
  Значение по умолчанию: `1048576` байт (1 МиБ); `0` отключает ограничение.
- Настройка пакетного конфига читает `HELPER_HTTP_LOG_DATA_MAX_LENGTH`.
  В ранее опубликованный конфиг приложения ключ нужно добавить отдельно; без ключа действует 1 МиБ.
- При создании DTO тело обрезается без разрыва многобайтного символа UTF-8.
  Признаки `info.request_data_truncated` и `info.response_data_truncated` устанавливаются только при усечении.
- В DTO и сериализованные данные очереди не сохраняется дополнительная копия полного усечённого тела.
- Поля `request_data_size`, `response_data_size` и `size` рассчитываются по исходным данным.
  Для текстов существующий подсчёт использует число символов, а не байт; лимит тела при этом задаётся в байтах.
- Если усечение нарушило JSON, действующая очистка при сериализации оставляет начало текста до 2048 символов.
  Тела в пределах лимита проходят прежнюю обработку; отключение нового лимита не отключает прежнюю очистку.

Реализация: [HttpLogDto](../../../src/Dto/HttpLogDto.php), методы `createByRequest()`,
`createByResponse()`, `limitData()` и `__serialize()`;
[настройка пакета](../../../config/laravel-helper.php).

Проверки в [HttpLogDtoTest](../../../tests/Unit/HttpLogDtoTest.php):
`createByResponseTruncatesLargeResponseData`, `createByRequestTruncatesLargeRequestData`,
`createByResponseKeepsResponseDataWithoutLimit`, `createByResponseUsesDefaultLimitWithoutConfigKey`,
`createByResponseTruncatesOutgoingRequestAndResponse`, `serializeKeepsPrefixOfTruncatedJson`,
`largeResponseKeepsOnlyBoundedPayload`.

## Исключения журналирования

- `http_log.in.exclude` и `http_log.out.exclude` должны учитывать полное тело до усечения.
  Маркер после границы лимита не должен приводить к сохранению ранее исключавшейся записи.
- Совпадение только с обрезанным префиксом не должно исключать запись, если полное тело не совпадало.
- При включённом журналировании DTO хранит результат проверки усечённых полей по настройкам на момент создания.
  Отпечаток префикса позволяет обнаружить его замену без хранения ещё одной копии; префикс не фильтруется повторно.
- Остальные поля проверяются при отправке задания по их текущим значениям.
  Например, сообщение `Connection failed`, добавленное после создания DTO запроса, участвует в исключениях.
- При замене тела через `merge()`, заполнение DTO или прямое присвоение решение для прежнего значения сбрасывается.
  Повторное присвоение того же значения сохраняет решение; сериализация и восстановление также его сохраняют.
- Формат сопоставления сохраняется: `имяПоля=значение`; имена тел в DTO: `requestData` и `responseData`.
  Для вложенных полей используется точечная запись, например `info.response_data_size`.
- Неусечённые тела и DTO, созданные напрямую, проверяются прежним общим механизмом.
  Выключенное журналирование и запрет методов HEAD/OPTIONS по-прежнему проверяются перед отправкой.
- Исключённая запись не отправляется в `HttpLogJob`, поэтому не сохраняется, не публикует `HttpLogEvent`
  и не вызывает связанные с заданием уведомления.

Реализация: `HttpLogDto::rememberDataExclusion()`, `HttpLogDto::notFoundConfigExclude()`,
[LaravelHelperService::canDispatch()/notFoundConfigExclude()](../../../src/Services/LaravelHelperService.php).
Используется прежний механизм сопоставления пакета `atlcom/helper`, без второго набора правил шаблонов.

Проверки в [HttpLogDtoTest](../../../tests/Unit/HttpLogDtoTest.php): `truncatedBodyPreservesExclusion`,
`truncatedPrefixDoesNotCreateExclusion`, `truncatedBodyKeepsExclusionsForUpdatedMetadata`,
`truncatedBodyRechecksReplacement`, `untruncatedBodyKeepsExistingExclusion`.
Выключенное журналирование проверяет `disabledLoggingDoesNotEvaluateBodyExclusions`;
проверка отправки использует подмену шины заданий, без записи в БД.

Известное ограничение существующего сопоставления: wildcard-шаблоны с `*` используют `fnmatch()`.
На проверенном PHP 8.5.4 строки длиннее 4096 символов вызывают предупреждение, преобразуемое Laravel в исключение.
Исправление этой отдельной проблемы не входит в изменение; сценарии больших тел проверяются регулярным
выражением `/DO_NOT_LOG/` на синтетических данных.

## Потоковые ответы и файлы

- Для `StreamedResponse` сохраняется описание типа ответа; callback потока не исполняется журналированием.
- Для существующего файла `BinaryFileResponse` размер и MIME-тип берутся из файла, но его тело не включается в журнал.
- Если файл уже удалён после отправки, используются `Content-Length` и `Content-Type` ответа.
  При отсутствии заголовка длины размер равен нулю; восстановление удалённого файла не требуется.

Путь выполнения: [HttpLogMiddleware::terminate()](../../../src/Middlewares/HttpLogMiddleware.php)
или обработчики HTTP-клиента, затем `HttpLogDto` и [HttpLogJob](../../../src/Jobs/HttpLogJob.php).
Проверки: `createByResponseUsesHeadersWhenBinaryFileIsDeleted`, `createByResponseUsesExistingBinaryFile`.

## Проверка и выпуск

Целевой набор: `php vendor/bin/phpunit --do-not-cache-result tests/Unit/HttpLogDtoTest.php`.
Он создаёт синтетические HTTP-сообщения, не обращается к БД или сети; файловые тесты удаляют свои файлы.
При запуске следует направлять `sys_temp_dir` в отдельный временный каталог текущей проверки.
Полный набор тестов пакета требует отдельной проверки изоляции БД и остальных ресурсов.

Миграции и изменения HTTP API не требуются. Существующие рабочие настройки автоматически не меняются.
Долгоживущие процессы приложения должны получить новую версию кода штатным способом выпуска.
